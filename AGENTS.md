# Agent guidance

## Solve the root cause

- Investigate the real root cause before changing code. Compare viable solutions instead of defaulting to a patch or workaround.
- Prefer a sound, maintainable fix. Do not dismiss the best solution just because it requires more work or an architecture change.
- When a broader change is the better solution, explain why, outline its scope, effort, and tradeoffs, and recommend it. Present it as an option for the user to decide before making a substantial architecture change.
- If proposing a temporary workaround, clearly state its limitations and what remains to fix the root cause.
- Keep solutions proportional to the problem; avoid unnecessary complexity.
